# Team Working Agreement, Definition of Done, and Role Guide

Project: POWER-HOUSE HOPE Project (Information Management)
Sprints: 4 sprints x 2 weeks = 8 weeks

## 1. Team Working Agreement

**Communication**
- Main channel: Messenger group chat.
- Daily check-in in the chat: what I finished, what I'm doing next, anything blocking me.
- Team meeting: [day/time], 15 to 30 minutes, once or twice a week.
- Reply to messages within 24 hours. If you will be away, tell the group beforehand.

**Working in GitHub**
- `main` is protected. Nobody commits to it directly.
- One task = one branch = one pull request.
- Fill in the PR template and write the task ID (e.g. S1-DEV-03).
- At least 1 teammate must approve a PR before it is merged.
- Post the PR link in Messenger so the reviewer sees it. Review within 24 hours.
- Link your PR to its issue (e.g. Closes #17) and assign yourself on both the issue and the PR.

**Blockers and absences**
- Tell the Scrum Master as soon as you are stuck. Do not wait for the next meeting.
- The Scrum Master logs it in the impediment log and follows up.

**Respect**
- Give feedback on the work, not the person.
- Everyone's tasks are in the Task Plan sheet. Keep your row's status and PR link up to date.

## 2. Definition of Done

A task is Done only when all of these are true:
- [ ] The work is complete and checked by the author
- [ ] A pull request was opened with the PR template filled in
- [ ] A teammate reviewed and approved the PR
- [ ] The PR is merged into `main`
- [ ] The PR link is pasted in the Task Plan sheet and the status is set to Merged
- [ ] No passwords or secrets are in the repo
- [ ] The PR is linked to its issue, and the issue and PR both have an assignee
